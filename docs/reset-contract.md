# Сброс пароля — контракт

Версия: 0.1 (реализовано на бэкенде и в панелях). Дополняет
[`signup-contract.md`](signup-contract.md) и `docs/openapi.yaml`.

## Зачем

У клуба, DJ и оператора платформы была только одна дверь: логин. Забытый пароль
означал «заведи новый аккаунт» (на стенде) или «пиши оператору» (в проде).
Теперь есть отдельный публичный путь восстановления — и он честный: письма
отправляются только там, где есть почтовый провайдер.

## `POST /v1/auth/password/reset-request` (публичный)

```json
{ "email": "owner@club.test", "role": "club" }
```

`role` — `club` | `dj` | `admin`, по умолчанию `club`.

| Ответ | Когда |
|---|---|
| `202 {"requested": true}` | запрос корректен — **независимо от того, существует ли адрес** (защита от перечисления аккаунтов) |
| `202 {"requested": true, "reset_url": "/reset-password/<token>", "expires_at": "…"}` | на стенде с `DROPIT_RESET_REVEAL_TOKEN=1` и существующим аккаунтом |
| `400 validation_failed` | пустой/кривой e-mail или неизвестная роль |
| `429 rate_limited` | больше 5 запросов за час на адрес или на IP |
| `503 external_service_unavailable` | у процесса нет БД |

## `POST /v1/auth/password/reset` (публичный)

```json
{ "token": "<64 hex>", "password": "<новый, 8..128>" }
```

| Ответ | Когда |
|---|---|
| `204` | пароль заменён |
| `400 validation_failed` | длина пароля вне 8..128 (**токен не сгорает**) |
| `401 invalid_reset_token` | токен неизвестен, уже использован или просрочен — одно сообщение на все случаи |
| `503 external_service_unavailable` | у процесса нет БД |

## Правила

- Токен: 32 случайных байта, в БД только `sha256`. Живёт 30 минут, одноразовый
  (атомарный `UPDATE … WHERE used_at IS NULL AND expires_at > now() RETURNING`).
- Успешный сброс отзывает **все** refresh-токены субъекта: сброс пароля — это
  ещё и выход со всех устройств.
- Пароли — Argon2id, как в логине (`auth::hash_password`).
- Ссылка всегда пишется в `tracing::info!`; пароль — никогда.
- Миграция: `crates/infra-db/migrations/0015_password_reset.sql`.

## Почта

Провайдера в этом деплое нет. Пока его нет, стенд работает через
`DROPIT_RESET_REVEAL_TOKEN` — сервер возвращает ссылку в теле ответа, и UI
показывает её человеку вместо «проверьте почту», которая останется пустой.
**В проде флаг обязан быть выключен**, иначе ссылку получит любой, кто знает
адрес. Ответ без флага неотличим от ответа на несуществующий адрес — так и
задумано.

## UI

- `/reset-password` — запрос ссылки: тип аккаунта, e-mail.
- `/reset-password/:token` — новый пароль: поле с раскрытием, повтор,
  локальная проверка длины и совпадения.
- `503` показывается как «сброс ещё не включён на этом сервере», а не как ошибка
  ввода; `401` — как «ссылка больше не действует» с предложением запросить новую.

Ссылки на восстановление стоят на входах: `/login` и `/dj/login` (`?role=dj`).
