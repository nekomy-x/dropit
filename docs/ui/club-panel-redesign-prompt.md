# Промт: редизайн панели клуба DROP IT

> Область: `apps/web-club` (Overview, Live room, DJs, Pricing, Earnings).
> Задача: убрать «квадраты с закруглением», собрать честный Bento-экран с
> вмеренными радиусами (1rem), минимальными обводками, спокойной абстракцией и
> аккуратным современным движением, попутно исправив функциональные дефекты.
> Документ самодостаточен: §1 — то, что вставляется в новую сессию агента-лида,
> остальное агент читает из этого же файла.

---

## 0. Как этим пользоваться

1. Открыть новую сессию в DSH в корне репозитория.
2. Вставить **§1 целиком** — это мастер-промт для лида.
3. Лид сам создаёт команду и задачи (§6), роли берут тексты из §8.
4. Приёмка — по §7, без «на глаз»: цифры, скриншоты, автотест.
5. Если лид упирается в спорное решение — §9, там уже зафиксированы ответы на
   конфликты с `AGENTS.md` и границы области.

## 1. Мастер-промт (копировать целиком)

```text
Ты — лид агентной команды, которая переделывает панель клуба DROP IT
(репозиторий: текущая рабочая папка, приложение apps/web-club).

МИССИЯ
Панель клуба сейчас выглядит как набор одинаковых тёмных прямоугольников с
крупным скруглением и обводкой по периметру, тянется на два экрана, часть цифр
на доске — локальная имитация, а подписи не совпадают с тем, что реально
считает API. Нужно переделать её в спокойную операционную Bento-доску
«ночного зала»: вмеренные радиусы (база 1rem = 16px), минимум рамок, честные
данные, ясный следующий шаг, аккуратная абстракция и простое современное
движение. Функциональные дефекты чинятся в том же проходе, а не «потом».

ПЕРЕД ЛЮБЫМ ДЕЙСТВИЕМ ПРОЧИТАЙ
1. AGENTS.md, PRODUCT.md, DESIGN.md в корне.
2. docs/ui/club-panel-redesign-prompt.md — целиком (§2 контекст, §3 диагноз,
   §4 контракт дизайна, §5 функционал, §6 процесс, §7 приёмка, §8 роли, §9 границы).
3. docs/ui/README.md (дизайн-источник и брендовая волна).
4. Код: apps/web-club/src/pages/DashboardPage.tsx, src/dashboard/*,
   src/components/Layout.tsx, src/operations.css, src/index.css.

ЗАГРУЗИ НАСТАВЛЕНИЯ (skills) И СЛЕДУЙ ИМ, НО ИЕРАРХИЯ ТАКОВА:
AGENTS.md + §4 этого файла > любые общие дизайн-скиллы.
Лид: impeccable, redesign-existing-projects, design-taste-frontend.
Дизайн-система: refactoring-ui, make-interfaces-feel-better, design-token-audit.
Движение: animation-principles, motion-system.
Проверка: webapp-testing, accessibility-audit, ux-heuristics, design-qa-checklist,
critique-composition, critique-visual-hierarchy, critique-typography,
critique-brand-consistency, ui-typography, loading-states, error-handling-ux.
Скиллы, написанные под лендинги и «вау-сайты», здесь запрещены как источник
направления: это рабочий инструмент под давлением времени, а не портфолио.

ЖЁСТКИЕ ПРАВИЛА
- Радиус поверхностей — ровно 16px. Вложенные плитки 12px, контролы 10px,
  пилюля только у статус-чипа и бегунка сегмент-контрола. Ничего 24/28/32px.
- Панель без обводки. Разделение — уровни поверхности, воздух и типографика.
  Рамка допустима только у полей ввода, у строк таблиц (1px, ≤6% белого) и как
  focus-ring. Никаких теней вместо рамок, никаких double-border и dashed.
- Один зелёный: #00FF87 (+ #00D873 hover, тинты 8/14%). #10B981/#22C55E и
  прочие «вторые зелёные» удалить.
- Движение: только transform/opacity/цвет, 120–260ms, ease-out; никакой
  хореографии входа, параллакса, скролл-анимаций, петель и пульсирующих
  свечений. Всё умирает под prefers-reduced-motion.
- Данные не выдумывать. Каждая цифра помечена: live (API), preview (локальная),
  unavailable. Тост «сохранено» для локальной мутации запрещён.
- Никаких фейковых метрик, заглушек вместо работающих элементов, «demo» вместо
  API там, где endpoint уже есть.
- Не трогать: /connect, apps/web-admin, apps/web-dj, apps/mobile-*, контракты
  API. Новые зависимости не добавлять (motion и auto-animate уже стоят).
- Не переписывать маршруты, авторизацию, навигацию по смыслу.

ПРОЦЕСС (детали в §6)
Ты работаешь командиром через инструменты команды: spawn_teammate (роли из §8),
team_task_create / team_task_update (задачи с write_scopes и blocked_by),
send_message (уточнения), wait_agent (ожидание), list_agents (состояние).
Сначала G0 (замеры и доказательства), затем контракт (G1),
потом каркас и примитивы (G2), доска (G3), остальные страницы (G4), функционал
(G5), проверка (G6), красная команда (G7), документация (G8). Пишущие агенты
работают в непересекающихся файлах, скоупы фиксируются в задачах; один файл —
один писатель в один момент. Каждую фазу закрывает артефакт: замеры, скриншоты,
список дефектов с file:line. Автор изменения не имеет права принимать свою
работу: верификатор и красная команда — отдельные агенты.

ПРИЁМКА (детали в §7)
Гейт закрыт только при зелёном автотесте scripts/club-ui-check.mjs, зелёных

не смогла найти новых дефектов P0/P1 в двух раундах подряд.

ОТЧЁТ В КОНЦЕ
1) что изменилось по фазам; 2) таблица «до/после» из §7.4; 3) какие функции
починены и какие осознанно остались preview (с причиной); 4) что осталось за
границей и требует отдельной задачи; 5) путь к скриншотам и к отчёту приёмки.
```

## 4. Контракт дизайна v2 — «Bento / measured radius»

Направление: спокойная ночная операционная доска. Тёмный фон, три уровня
поверхности, один зелёный, типографика как иерархия, воздух вместо рамок,
ограниченная абстракция в фоне и очень сдержанное движение.

### 4.1 Принципы

1. Один экран — один ответ: «что сейчас с залом и что мне сделать дальше».
2. Разделение — поверхностью и расстоянием, не обводкой.
3. Радиус вмеренный: 16px — потолок, и он же база. Ничего «пузырящегося».
4. Одинаковые элементы выглядят одинаково на всех страницах панели.
5. Абстракция — фон, а не украшение: тише текста, не мешает чтению.
6. Движение подтверждает действие, а не развлекает.
7. Всё, что не сохраняется, помечено.

### 4.2 Сетка и композиция

| Параметр | Значение |
|---|---|
| Сетка | 12 колонок (≥1280), 8 (768–1279), 1 (≤767); `gap`: 16 / 12 |
| Спаны | 3/4/6/8/12; `grid-row: span 2` только если контент реально двухрядный |
| Приоритет | 4–6 плиток в первом экране 1440×900, остальное — ниже |
| Ширина | одно ограничение на всю панель (сейчас конкурируют 1280/1320/1360 — E4) |
| Бюджет высоты | ≤1700px при 1440×900; ≤3000px при 390×844 |
| Максимум плиток | 8 (Overview). Остальное — переходы в разделы, а не новые плитки |
| Пустота снизу | ≤24px от последнего элемента плитки, иначе плитка растянута неоправданно |

Три полосы доски (визуально разделены только отступом 24–32px, без заголовков-«eyebrow»):

1. **Состояние зала** — режим/смена, вместимость, поток гостей, сейчас играет.
2. **Деньги и запросы** — чаевые, средний чек, число запросов, net с честной подписью.
3. **Люди и доступ** — диджеи/смена, зоны, QR.

Убрать с Overview: форму правил и музыки (F12), дубли таблиц (F9). «Live room»
остаётся единственным местом, где открывают и закрывают смену.

### 4.3 Шкала радиусов

| Токен | Значение | Где |
|---|---|---|
| `--r-surface` | **16px** | панели, модальные окна, крупные контейнеры |
| `--r-tile` | **12px** | плитки внутри панели, инпут-группы, вложенные блоки |
| `--r-control` | **10px** | кнопки, поля, сегмент-контрол, иконочные кнопки |
| `--r-chip` | **999px** | только статус-чип и бегунок сегмент-контрола |

Правила:
- Ничего выше 16px. 24/28/32px удаляются полностью.
- Вложенный радиус концентричен: `r_inner = max(8, r_outer − 4)`.
- Разделители, строки таблиц, полосы прогресса — без скругления (или 999 у пилюли-метра).
- Внутри одной панели не больше двух разных радиусов.

### 4.4 Поверхности и границы

| Уровень | Цвет | Использование |
|---|---|---|
| canvas | `#090A0F` | фон приложения |
| surface | `#11131A` | панель на доске |
| raised | `#171A22` | плитка, контрол, hover |
| inset | `#0D0F15` | поля ввода, «колодцы», полосы данных |
| hairline | `rgba(235,240,250,.08)` | только там, где разрешено |

Политика рамок:
- **Панель — без рамки.** Никакого `border`, никакого inset-box-shadow вместо него.
- Разрешено: `1px` у полей ввода, `1px` разделитель строк таблицы (≤6% белого),
  focus-ring `2px` `#00FF87` с `outline-offset: 2px`, выделенная плитка —
  тинт-фон + лезвие 2px акцента слева (не рамка вокруг).
- Запрещено: dashed, double, рамка + тень одновременно, «ободок» у чипа
  (чип = тинт-фон), рамка у вложенной карточки внутри карточки.
- Тени: только скрим модалки. Никаких `box-shadow` с размытием на поверхностях.

### 4.5 Цвет

| Роль | Значение |
|---|---|
| Акцент (живое/главное/успех) | `#00FF87`, hover `#00D873`, тинты `rgba(0,255,135,.08)` и `.14` |
| Текст на акценте | `#06130C` |
| Основной текст | `#F1F4F7` |
| Вторичный | `#B0B8C3` |
| Приглушённый | `#858E9C` (только для ≥12px; для мелкого текста — `#9AA3B0`) |
| Предупреждение | `#FFC65B` (тинт 10%, без рамки) |
| Ошибка | `#FF6B6B` (тинт 10%, без рамки) |

Запрещено: `#10B981`, `#22C55E`, `#7ee2a8`, `#8ed3f4`, `#f2d089` и любые
«вторые зелёные»; градиенты; свечения; цвет как единственный носитель статуса
(рядом всегда текст или форма).

Контраст проверен расчётом (WCAG 2.1, отношение яркостей) — все пары выше
проходят AA для обычного текста:

| Пара | Отношение |
|---|---|
| `#F1F4F7` на `#11131A` | 16.8:1 |
| `#B0B8C3` на `#11131A` | 9.3:1 |
| `#858E9C` на `#11131A` | 5.6:1 |
| `#9AA3B0` на `#11131A` | 7.3:1 |
| `#00FF87` на `#11131A` | 13.8:1 |
| `#06130C` на `#00FF87` | 14.2:1 |
| `#FFC65B` / `#FF6B6B` на `#11131A` | 11.9:1 / 6.7:1 |

**Важно:** текущий токен `#666666` из `DESIGN.md` даёт **3.06:1** на `#191919`
и **3.31:1** на `#101010` — ниже AA. Поэтому `#858E9C`/`#9AA3B0` заменяют его,
а `#666666` удаляется из палитры панели, а не переносится.

### 4.6 Типографика

- Реально загружаемый Inter — единственное семейство интерфейса. `Geist` либо
  подключить локально (самохостинг, вес ≤2 файлов), либо убрать из CSS.
  Моно — системный стек (`ui-monospace, SFMono-Regular, Menlo`) и только для ID,
  времени, сумм с `font-variant-numeric: tabular-nums`.
- Шкала: **28 / 20 / 15 / 13 / 12 / 11** (не больше 6 размеров на экране).
  Значение метрики — 28 или 20, не «clamp до 34».
- Верхний регистр с трекингом — максимум **один** на экран (название зала/смены).
  Чипы, метки, статусы — обычный регистр.
- Межстрочный: 1.2 для значений, 1.45–1.55 для текста. Максимум 62ch для абзаца.
- Заголовки панелей — 15px/600; подпись под ними — 12px, не серее `#858E9C` при 12px.
- Никаких обрезанных заголовков и `text-overflow` на числах.

### 4.7 Абстракция (разрешённая и ограниченная)

Задача абстракции — дать доске «воздух» и характер, не мешая чтению.

- Бюджет: **один** фоновый абстрактный элемент на экран, `pointer-events: none`,
  контраст к поверхности ≤6%, без размытия, без цветных пятен.
- Разрешено: сетка точек 24px (`radial-gradient` точки 1px, 3–4% белого);
  концентрические дуги 1px (4%); статичная «волна» бренда (`brand_wave`) как
  тонкая полоса у края доски; крупная геометрическая форма, обрезанная краем
  панели, залитая тинтом акцента ≤5%.
- Предпочтительнее «абстракция из данных»: дуга занятости зала, лента потока
  гостей, сетка QR-ячеек — форма, которая кодирует состояние, а не украшает.
- Запрещено: mesh-градиенты, размытые блобы, зерно/шум, стекло, 3D-объекты,
  анимация фона, абстракция под текстом мельче 14px.
- Абстракция отключается одним токеном `--abstract-opacity: 0` (для
  reduced-motion, печати, отладки и скриншотов-эталонов).

### 4.8 Движение

| Токен | Значение |
|---|---|
| `--dur-fast` | 120ms |
| `--dur-base` | 180ms |
| `--dur-slow` | 260ms |
| `--ease-out` | `cubic-bezier(.22, 1, .36, 1)` |
| `--ease-std` | `cubic-bezier(.4, 0, .2, 1)` |

Разрешённые примитивы:

1. Hover: фон поверхности + `translateY(-1px)` за 120ms (только у кликабельных плиток).
2. Press: `scale(.99)` за 90ms.
3. Сегмент-контрол: бегунок едет `transform` за 180ms.
4. Тост: вход `translateY(8px)` + opacity 180ms, выход 120ms, автоскрытие ≥8s,
   пауза при hover/focus.
5. Смена значения метрики: кросс-фейд 120ms (без «прыжка» ширины).
6. Переупорядочивание списка: `@formkit/auto-animate` (уже в зависимостях).
7. Рисование линии графика один раз при получении новых данных — 500ms, только
   `stroke-dashoffset`. Не при монтировании страницы.

Запрещено: входные каскады плиток, `animation-delay`-стаггеры на доске,
параллакс, scroll-linked, бесконечные пульсации (кроме одной точки «live» —
только opacity, 2s), анимация `width/height/top/left/margin`, `filter: blur()`,
переходы дольше 300ms.

Обязательно: `@media (prefers-reduced-motion: reduce)` обнуляет всё, контент
никогда не зависит от анимации.

### 4.9 Компоненты (минимальный набор)

| Компонент | Правила |
|---|---|
| `Panel` | surface-16px, padding 20–24px, без рамки и тени, заголовок 15/600 + описание 12px, слот действия справа |
| `Metric` | метка 12px, значение 28/20 (tabular), источник данных — маленький чип `live/preview` |
| `Tile` | вложенная плитка 12px на `raised` или `inset`, без рамки |
| `Segmented` | inset-подложка 10px, бегунок 10px, `role="radiogroup"`, стрелки клавиатурой |
| `Chip` | пилюля, тинт-фон, без рамки, обычный регистр, ≤3 на плитку |
| `ListRow` | 44px минимум, разделитель 1px ≤6%, hover — `raised` |
| `Meter` | 6px высотой, трек `inset`, заполнение акцентом, число рядом текстом |
| `QRBlock` | QR на `#FFFFFF` 12px, подпись моно, действия: Rotate (с подтверждением), Pause |
| `Toast` | 8s+, `role="status"`, кнопка «Отменить» там, где есть откат, пауза при hover |

### 4.10 Мобильная версия (390×844)

- Порядок: состояние зала → 4 ключевых числа сеткой 2×2 → сейчас играет →
  деньги → зоны → QR → расписание (свёрнуто «Показать 3 события»).
- Панели 16px, внутренние отступы 16px, gap 12px.
- Нижняя навигация остаётся (5 пунктов), главное действие — в шапке, не в
  плавающей кнопке.
- Никаких горизонтальных скроллов; таблицы превращаются в список строк.
- Бюджет высоты — ≤3000px, первый экран отвечает на «что с залом».

### 5.3 Взаимодействие

- Деструктивные действия (Take over, Pause all, Rotate QR, закрытие смены):
  подтверждение в две ступени внутри контрола или короткое диалоговое окно,
  затем откат через тост 8s с «Отменить», где откат возможен.
- На время запроса — `disabled` + индикатор в кнопке; повторный клик не отправляет второй запрос.
- Ошибки: один баннер + retry; текст говорит, что произошло и что делать.
- Клавиатура: ⌘K палитра работает; `Escape` закрывает; сегмент-контрол —
  стрелки; фокус видим всегда; порядок табуляции совпадает с визуальным.
- Статус не только цветом: рядом слово (`live`, `preview`, `ошибка`).
- Цели нажатия ≥44px на мобиле, ≥36px на десктопе.
- Тосты: ≥8 с, пауза при hover/focus, «Отменить» там, где возможен откат,
  одно объявление для скринридера (не `aria-live` + `role="status"` сразу).
- Закрытие смены — подтверждение с явным «необратимо» текстом (F13).
- Смена цены для гостей — подтверждение со старой и новой ценой (F16).
- Suspend/Restore DJ — подтверждение + уведомление о результате (F14).
- Свежесть данных не обновляется чаще раза в 5–10 с и только по факту запроса (F5, F6).

### 6.3 Правила работы команды

1. Задачи — через `team_task_create` с полями `write_scopes` (из §6.1) и
   `blocked_by` для зависимостей. Статус — `claim` → работа → `complete`.
2. Один файл — один писатель в единицу времени. Пересечение скоупов — остановка
   и сообщение лиду, а не «попробую аккуратно».
3. Каждый вывод проверки — с доказательством: `file:line`, число, путь к
   скриншоту. «Выглядит лучше» не аргумент.
4. Автор не принимает свою работу. Verifier и Red team — отдельные агенты.
5. Красная команда обязана искать: пустоты, лишние рамки, несоответствие
   радиусов, ложные подписи данных, недоступные с клавиатуры элементы,
   анимации без reduced-motion, пиксельные сдвиги между состояниями.
6. Максимум 3 раунда правок после G6. Если гейт не закрывается — лид
   останавливается и выносит пользователю список из ≤5 пунктов с вариантами.
7. Никаких «потом поправлю»: незакрытый пункт §7.1 = гейт не сдан.

### 7.2 Автотест `scripts/club-ui-check.mjs`

Запускается так: `npm run dev:demo` → `node scripts/club-ui-check.mjs`.
Тест опирается на контракт разметки, который обязан ввести G2:
`data-surface` (панель/плитка), `data-control` (кнопка/поле/сегмент),
`data-metric` + `data-source="live|preview|unavailable"`. Без этих атрибутов
проверки 1, 2 и 11 невыполнимы — значит, контракт разметки входит в гейт G2.

Проверки (каждая — отдельный assert с понятным сообщением):

1. Множество `border-radius` у `[data-surface]` = `{16px}`; у `[data-control]` ⊆ `{10px, 12px, 999px}`.
2. Ни один `[data-surface]` не имеет `border-width > 0` и `box-shadow` с blur > 0
   (исключения — `input`, `select`, `textarea`, `[data-allow-border]`).
3. `document.body.scrollHeight` при 1440×900 ≤ 1700; при 390×844 ≤ 3000.
4. Нет горизонтального переполнения при 320/390/768/1024/1440.
5. Все интерактивные элементы имеют доступное имя (axe + собственный проход).
6. Минимальная цель нажатия на мобиле ≥44×44 (кроме inline-ссылок).
7. Focus-ring виден на первых 10 табах (`outline-width ≥2px`).
8. `prefers-reduced-motion: reduce` → `document.getAnimations()` пуст.
9. Число уникальных `font-size` на экране ≤6; нет `font-size < 11px`.
10. Верхний регистр с letter-spacing: ≤1 элемент на экран.
11. Каждая `[data-metric]` имеет `data-source` с одним из трёх значений; при
    наличии `preview` на экране есть общий баннер `[data-preview-banner]`.
12. Контраст: каждый текстовый узел ≥4.5:1 (≥3:1 для ≥24px) — отчёт по нарушениям.
13. Ни одного запроса к `code.iconify.design`/`fonts.googleapis.com` (перехват route).
14. Нет `console.error` и `pageerror` при загрузке.
15. Скриншоты 1440×900, 1024×768, 390×844 сохраняются в `output/club-redesign/<run>/`.
16. Печать отчёта в `output/club-redesign/<run>/report.json` + человекочитаемый `report.md`.

Тест живёт в репозитории и остаётся после задачи; пороги меняются только через ревью лида.

### 7.3 Ручные проверки

- Клавиатурный проход по доске: Tab/Shift+Tab, ⌘K, Escape, стрелки в сегменте.

## 9. Границы, конфликты и принятые решения

1. **`AGENTS.md` запрещает Bento и декор, но пользователь просит Bento с
   абстракцией.** Приоритет — прямое указание пользователя. Оформляется как
   документированное исключение в `DESIGN.md` (раздел уже существует), с
   бюджетом: одна абстракция на экран, ≤6% контраста, отключается токеном.
   Всё остальное из запретов `AGENTS.md` остаётся в силе: ни градиентов, ни
   свечения, ни стекла, ни зерна, ни параллакса.
2. **28px были согласованы раньше.** Новое указание (1rem) отменяет старую
   договорённость; `DESIGN.md` переписывается, история остаётся в ADR.
3. **Не в области задачи:** `/connect` (отдельный визуальный мир), консоль DJ,
   `apps/web-admin`, мобильные приложения, контракты API (кроме отдельной
   задачи с тестом), авторизация, маршруты.
4. **Мок-данные нельзя просто удалить**: часть сценариев ещё не имеет endpoint'ов.
   Правило — не удалять, а маркировать и не выдавать за живое.
5. **Если endpoint отсутствует**, но функция нужна на доске: оставить как
   `preview` с честным текстом, а не имитировать сохранение.
6. **Порог «красиво»** — только через чек-лист §7.1 и таблицу §7.4. Вкусовые
   правки без доказательств не принимаются.
7. **10 ложных success-тостов и необратимое закрытие смены без подтверждения —
   это не косметика, а риск доверия и потери данных.** Если бюджет не
