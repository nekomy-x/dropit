# Быстрый заказ по QR

Публичный маршрут: `/join?token=<QR token>`. Совместимый маршрут: `/room?token=…`.
Все три места выдачи QR (смена, обзор клуба, QR Studio) кодируют одну HTTPS-ссылку.
Ни вход в кабинет, ни установка приложения для заказа не нужны.

## Сценарий

1. Камера телефона открывает ссылку на комнату. Android App Link / iOS Universal Link
   открывает установленное приложение сразу в поиске этой комнаты.
2. Без приложения браузер сразу получает гостевой device-token и join-грант.
   Пользователь видит реальный клуб, DJ и цену из API, ищет и выбирает трек.
3. На этом же экране открывается Stripe Payment Element; доступные карты и
   кошельки определяет Stripe для устройства и аккаунта. Карточные данные
   остаются внутри Stripe. Пользователь видит итог и подтверждает условия.
4. После авторизации и backend confirm показан номер запроса. Обработка
   платежа обозначена отдельно: экран не утверждает, что деньги уже списаны
   или DJ уже принял трек. Финальный захват выполняет существующий backend.

Заказ, исходные ключи идемпотентности и PaymentIntent сохраняются в sessionStorage;
идентификатор гостя — в localStorage. Повтор и возврат из 3DS продолжают тот же
заказ. Статус в query не считается подтверждением: проверяется Stripe intent.
Возврат из 3DS идёт через `/guest/payment-return`, который не привязан к
приложению: банковское подтверждение веб-платежа не перехватывается ОС и
продолжается в том же браузере с тем же guest device-token.
Незавершённая оплата другой комнаты блокирует новый заказ и даёт ссылку возврата.
Смена трека после создания оплаты не создаёт второй заказ; нужно завершить текущий.
Недействующий QR, пауза, отсутствие цены, сеть, пустой поиск и недоступный Stripe
имеют явные состояния. На mock-стенде доступна явно обозначенная тестовая оплата.

## Тестовая оплата без карты

Если backend работает с `MockStripe`, join возвращает `test_payments: true`,
а intent — `test_mode: true`. Веб и приложение показывают способ «Тестовая оплата»
и предупреждение об отсутствии списания. Ключ Stripe и реквизиты карты не нужны.
Заказ и intent создаются через обычные API. Подтверждение выполняется через
`POST /v1/payments/{id}/test-confirm`: тот же контроль владельца/сессии,
обычные записи ledger и outbox. После успеха виден номер заказа и текст «без списания».
Неоплаченная/отклонённая операция не подменяется успехом на клиенте.

Способ включается фактическим серверным mock-провайдером (по умолчанию без ключей
Stripe), не параметром URL и не настройкой браузера. С настоящим Stripe, включая
Stripe sandbox, endpoint возвращает 404; старые реальные intent нельзя подтвердить
тестово после переключения провайдера. Повторы возвращают тот же результат без
повторной проводки. Для проверки пути Stripe с тестовыми картами используется
отдельный Stripe sandbox с соответствующими ключами, как обычная оплата.

## Внешний вид

Публичный заказ использует общую дизайн-систему DROP IT: Inter, нейтральный
графит, зелёный `#00FF87` в тёмной теме и `#087A4C` в светлой, тёмный текст
на яркой кнопке. Цвета наследуются из `packages/ui/tokens.css`; отдельной
синей палитры нет. `guest-tokens.css` содержит только совместимый alias
для текста на акценте. Кнопки имеют радиус 10px, в шапке — общий BrandLogo.
Выбор трека, тестовая/реальная оплата и подтверждение используют один акцент.
Flutter-токены и фирменный знак также используют зелёную палитру.
Фокус в поиске трека и ручном вводе QR обозначается только зелёным курсором:
без обводки, подчёркивания и тени, включая нативное оформление Safari.
У кнопок и чекбокса сохраняется видимый фокус клавиатуры.

## Настройка окружения

- В web-club задать `VITE_GUEST_STRIPE_PUBLISHABLE_KEY=pk_…` от того же Stripe
  аккаунта и режима, что `STRIPE_API_KEY` backend. Пересобрать веб.
- Для оплаты и App Links нужен доверенный HTTPS. Стенд
  `https://150.241.68.204` уже работает по HTTPS с IP-сертификатом и
  опубликованным Android assetlinks.json.
- Собрать Android APK с `-PdropitGuestHost=<домен>` при запуске Gradle
  (по умолчанию `dropit.club`). Путь App Link ограничен `/join`.
- Получить SHA-256 сертификата **фактически распространяемого APK** и выполнить
  `DROPIT_GUEST_ANDROID_SHA256=<отпечаток> node scripts/guest-app-links.mjs`
  до сборки web-club. Если applicationId изменён, также задать
  `DROPIT_GUEST_ANDROID_PACKAGE` и обновить package в `guest/links.ts`.
- Опубликовать `/.well-known/assetlinks.json` без redirect на том же HTTPS-домене.
  Nginx возвращает JSON или 404, никогда HTML SPA. Пока привязка не опубликована,
  кнопка «Открыть в приложении» использует Android intent с веб fallback.
- Для iOS задать `DROPIT_GUEST_HOST` в `ios/Flutter/{Debug,Release}.xcconfig`
  (по умолчанию `dropit.club`), включить Associated Domains в профиле подписи.
  До сборки web-club выполнить `DROPIT_GUEST_IOS_APP_ID=<TeamID.BundleID>
  node scripts/guest-app-links.mjs` с реальным Team ID и Bundle ID приложения.
  Скрипт создаёт `apple-app-site-association`; его нужно публиковать на том же
  HTTPS-домене без redirect. Обработчик `app_links` поддерживает cold/warm start
  и UIScene. Без установленного приложения на iPhone сразу работает веб-оплата.
  Веб не пытается угадывать наличие приложения таймером.

Проверка на устройстве: открыть новый QR без приложения; установить APK и проверить
тот же QR при закрытом и уже открытом приложении; проверить возврат из 3DS и сетевой
повтор. App Links требуют новой версии APK с обработчиком, старый APK их не получит.

Технические основания: [Flutter App Links](https://docs.flutter.dev/cookbook/navigation/set-up-app-links),
[Stripe Payment Element](https://docs.stripe.com/payments/payment-element).

## Проверка реализации

- Production build web-club, синхронизация UI, API docs — проходят.
- `guest-checkout-check.mjs` — 14 браузерных сценариев с API / Stripe fixtures,
  включая повтор, отказ карты и возврат из 3DS; реальные деньги не списывались.
- `panel-audit.mjs` — 720 проверок существующих панелей; `/join` и `/qr`
  дополнительно по 24 проверки в двух темах. `ui:check` — green.
- `qr-studio-check.mjs` — 32 проверки генерации и декодирования QR.
- Flutter: полный набор 214 тестов прошёл, включая тестовую оплату; 2 теста конкурентной выдачи
  device-token и повтора после ошибки также прошли. Dart analyze изменённой
  логики ссылок и состояния прошёл.
- Сервер: 19 платёжных e2e в отдельном PostgreSQL (повтор, lost-response replay,
  параллельная гонка, webhook, возвраты, тестовая оплата); дополнительно повторены
  3 теста тестового метода с проверкой параллельности, владения и запрета live/paused.
  Stripe unit/doc tests — проходят.
- Android APK для стенда собран: версия 0.1.1-test204, ARM64, зелёная палитра,
  отдельный пакет `com.example.dropit_guest.test204`. Подпись, адрес API,
  manifest App Link и полный SHA-256 скачанного APK проверены. Полный Xcode
  отсутствует, iOS build и автооткрытие на физических устройствах не проверены.
- После смены палитры: все 220 Flutter-тестов и 3 браузерных сценария тестовой
  оплаты прошли; мобильные снимки оплаты проверены в тёмной и светлой темах.

Отчёты и снимки лежат в `output/playwright/`; снимки `*-fixture.png` используют
тестовый клуб и тестового провайдера, а не данные действующего заведения.
