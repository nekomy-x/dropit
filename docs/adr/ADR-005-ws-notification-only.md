# ADR-005: WebSocket уведомляет, истина — REST/БД

**Статус:** принято для F4
**Дата:** 2026-10-12

## Решение

- WS — только канал уведомлений; источник истины — PostgreSQL + REST API.
- Аутентификация WS: `POST /v1/ws/ticket` → одноразовый билет TTL 30 с (Redis) → передаётся в `Sec-WebSocket-Protocol`. **JWT в query-параметрах запрещён** (утечка в логи Cloudflare/Loki).
- Проверка прав на каждую подписку: гость — только события своих request'ов (грант `session_guest` + фильтр по `guest_device_id`), DJ/клуб — по роли и привязке.
- Reconnect: экспоненциальный backoff 0.5→8 с + jitter; после переподключения клиент получает **snapshot через REST** (гость — свои запросы, DJ — очередь), не «догоняющие» события.
- Fallback: при недоступности WS клиент сам переходит на REST-poll (30 с, только пока есть активный pending-запрос).

## Следствия

- Падение WS-шлюза не теряет данные: клиент после reconnect читает актуальное состояние.
- Redis single-use ticket защищает от replay перехваченного URL.
