# ADR-004: Схема Stripe Connect — ОТКРЫТ (блокер Q15)

**Статус:** ⛔ открыт; блокирует реализацию F5
**Дата:** 2026-10-12
**Ответ:** требуется согласование с бухгалтером/юристом владельца

## Вопрос

Какую схему Connect использовать для сплита «платформа + клуб + DJ»:

| Вариант | Механика | Плюсы | Риски |
|---|---|---|---|
| A. Destination charges (`transfer_data` + `application_fee`) | платёж сразу частично на аккаунт клуба, DJ — отдельный Transfer | проще кэш-флоу по клубу | DJ-трансфер с баланса платформы → нужен **float** |
| B. Separate charges and transfers (`transfer_group`) | полный платёж на платформу, потом Transfers | полный контроль, проще возвраты/disputes | требования Stripe к задержке трансферов, float обязателен |

## Обязательные пункты любого решения

1. **Float платформы**: DJ-трансферы идут с баланса платформы → оборотный резерв ≥ недельных DJ-долей; мониторинг доступного баланса перед payout-циклом.
2. Страна регистрации юрлица, валюта, supported payment methods, KYC-параметры (Q13/Q14) — до выбора.
3. Stripe Tax/VAT — кто налоговый агент, как фиксируется tax-строка в `split_snapshot`.
4. Модель комиссии провайдера: fee — расход платформы (позиция техкарты), но окончательная формула — с бухгалтером (в документах есть 3 конфликтующие версии).
5. Проверка applicability выбранной схемы к стране/валюте пилота.

## Безопасный временный режим

До закрытия ADR-004: **никакой интеграции Stripe вообще** (ни test, ни prod). Этапы F0–F4 от этого не зависят.

## Владелец должен подтвердить

- юрлицо и страну (Q13/Q14);
- вариант схемы (A/B) после консультации;
- источник float и его размер;
- налоговую модель.
