# ADR-003: Деньги — BIGINT минорные единицы, снимки тарифов, двойная запись

**Статус:** принято (инвариант, не подлежит пересмотру без ревизии всего платёжного цикла)
**Дата:** 2026-10-12

## Решение

1. **Все суммы — `i64`/`BIGINT` в минорных единицах валюты** (центах). Float запрещён в денежных расчётах всюду (Rust, SQL, сериализация). Арифметика — только `checked_*`; переполнение — ошибка, не паника.
2. **Цену запроса задаёт заведение**; комиссия DROP IT и доли клуба/DJ — конфигурация (`platform_settings` + per-club override). **Значения не задаются кодом** — строка настроек создаётся с NULL/`unset`, реальные значения вносит владелец (Q11/Q1).
3. **Снимок правил фиксируется в каждом платеже** (`payment.split_snapshot`, immutable после capture): смена тарифа действует только на новые запросы. История тарифов — append (`pricing_policy` с `valid_from/valid_to`), без UPDATE.
4. **Ledger — двойная запись, append-only**: каждая проводка сбалансирована (Σ записей `txn_id` = 0); исправление — сторнирующая проводка, не UPDATE. Счёт = `(account, currency)` с первого дня.
5. Возвраты/disputes — reversible через `refunded_minor`/`reversed_minor`; снятие денег «в никуда» невозможно.

## Следствия

- Сверка со Stripe сходится копейка-в-копейку.
- Мультивалюта не потребует миграции (счёт уже пара account+currency).
- Округление сплита (остаток цента → комиссии платформы) фиксируется при закрытии Q2/Q11.
