# ADR-001: Rust modular monolith, чистые домены

**Статус:** принято (проектное; финальное подтверждение — владелец/команда)
**Дата:** 2026-10-12
**Контекст:** КП предлагало NestJS; архитектурное решение и техкарта переключились на Rust.

## Решение

Backend — модульный монолит на Rust (Tokio/Axum/SQLx), workspace из крейтов:

- `common` — деньги, ошибки, идентификаторы (без зависимостей от фреймворков);
- `domain` — чистые домены (state machines, правила), не знают про HTTP/БД;
- `infra-db` — SQLx-пулы, репозитории, миграции;
- `gateway-api` — REST-бинарник (Axum).

Дополнительные бинарники (ws-gateway, workers, webhook-stripe) добавляются по фазам, **из той же кодовой базы**, когда их функциональность реально нужна (F4, F5) — не заранее.

## Следствия

- Нет микросервисов/Kubernetes на старте: Docker Compose для local, один процесс API.
- Вынос модуля в сервис в будущем — механический: домены не завязаны на транспорт.
- Риск bus-factor зафиксирован: рекомендованы минимум 2 Rust-разработчика; до подтверждения команды владелец принимает риск сознательно.

## Альтернативы

- NestJS (КП): быстрее старт, но хуже предсказуемость latency/памяти под пиковыми пятничными нагрузками и слабее типовые гарантии стейт-машин.
- Микросервисы сразу: отклонены — нет измеримой необходимости на MVP.
