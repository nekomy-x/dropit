# ADR-006: Каталог — статус ОТКРЫТ по лицензиям (B5)

**Статус:** 🟡 транспорт реализован (iTunes + Deezer); лицензии — открыты (B5)
**Дата:** 2026-10-12
**Реализовано (транспорт):** 2026-10-19

## Принятая механика (когда источники подтверждены)

1. Поиск выполняется **из клиентского приложения** (документы утверждают, что Apple блокирует серверные дата-центры для iTunes Search — требует проверки на реальном окружении).
2. Сервер **whitelist-валидирует** клиентский результат: домены cover/preview (например `*.mzstatic.com`, deezer), длины полей, canonical-ключ `source+source_id` пересчитывается и сверяется — защита от отравления кэша модифицированным клиентом.
3. Кэш: Redis по нормализованному `query+market` хранит **список id track_cache** (не копию метаданных); БД — upsert по `UNIQUE(source, source_id)`.
4. ISRC-обогащение — MusicBrainz серверно (rate 1 req/с).
5. Истекающие превью-URL: `preview_url_checked_at` + фоновый re-resolve.

## Открыто (блокер B5)

- Актуальные условия iTunes Search / Deezer / MusicBrainz API: права на метаданные, обложки, 30-сек превью в коммерческом продукте по странам.
- Реальная доступность клиентского поиска из стран пилота.
- Утверждение в КП «Spotify не отдаёт превью с 2024» — сверить с текущим состоянием.

## Следствия

F3 (каталог) не стартует до закрытия B5. Запросы/сессии/платформенные экраны от каталога не зависят; в тестовом контуре допускается только **явно помеченный** синтетический набор треков.

> Обновлено 2026-10-19: F3 стартовал на уровне **транспорта** — `HttpCatalog`
> делает реальные запросы к iTunes Search и Deezer; в тестах — `MockCatalog`
> на записанных JSON-фикстурах. Лицензии (B5) по-прежнему открыты → live
> поиск в прод включается после их закрытия.

## Реализация (транспорт каталога)

Транспортный слой — `crates/infra-catalog`; доменная валидация —
`crates/domain/src/catalog.rs`; роут — `GET /v1/catalog/search` в
`crates/gateway-api/src/catalog_routes.rs`.

- **Источники подключены**: iTunes Search API (`parse_itunes_search`,
  `parse_itunes_lookup`, URL `https://itunes.apple.com/search|lookup`, без
  API-ключа) и Deezer (`parse_deezer_search`, `parse_deezer_track`). Оба —
  через абстрактный `Transport` (reqwest в прод, фейковый в тестах).
  `SUPPORTED_SOURCES = ["itunes", "deezer"]`.
- **Нормализация**: `canonical_key` — стабильный ключ дедупликации
  `(artist|title)` без учёта регистра, диакритики (`fold_diacritics`),
  пунктуации и feat./prod.-суффиксов. `build_search_term` — построение терма.
- **ISRC**: `validate_isrc` проверяет структуру `CC-XXX-YY-NNNNN`.
- **Кеш-политика**: `cache_ttl` возвращает TTL в зависимости от наличия ISRC
  (треки с ISRC кешируются дольше). Канонический ключ `(source, source_id)`
  хранится в БД (`track_cache`, UNIQUE — миграция `0004`).
- **Ошибки**: `CatalogError` — `RateLimited` (429), `Timeout`,
  `Unavailable` (5xx/связь), `Decode`, `Config`; `is_transient` определяет
  право на резервный источник (iTunes → Deezer).
- **Маршрутизация**: `HttpCatalog` перебирает источники; `clamp_limit`
  зажимает `1..=25`; `encode_query_component` кодирует терм.

Покрытие: 88 тестов (unit + integration на JSON-фикстурах без сети:
`tests/itunes_parse.rs`, `tests/deezer_parse.rs`, `tests/normalize.rs`,
`tests/urls.rs`, `tests/mock.rs`).

## Что осталось открытым (B5)

- **Лицензии**: права на метаданные, обложки, 30-сек превью в коммерческом
  продукте по странам — iTunes Search / Deezer / MusicBrainz. Транспорт
  написан, но live-использование в прод требует подтверждения прав.
- **MusicBrainz ISRC-обогащение** (серверно, rate 1 req/с) — не подключено.
- **Re-resolve истекающих превью-URL** (`preview_url_checked_at` + фоновый
  воркер) — не реализовано.
- **Доступность клиентского поиска из стран пилота** — не проверена на
  реальном окружении.
- Утверждение «Spotify не отдаёт превью с 2024» — сверить с текущим состоянием.

Без закрытия B5 live-каталог в прод не включается; `HttpCatalog` доступен
для разработки/тестирования, в e2e используется `MockCatalog`.
