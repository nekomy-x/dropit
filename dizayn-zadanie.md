**Дата:** октябрь 2026
**Источник:** анализ текущего макета (pen.dev) + ТЗ (`trebovania.md`) + архитектурное решение (`arhitekturnoe-reshenie.md`)
**Стиль:** существующий — чёрный фон, белый текст, неоново-зелёный акцент, «ночная» атмосфера

## 0. Правки существующих экранов (клиентское приложение)

1. **Цена запроса.** На одном экране отображается €5.00 — вместо фиксированной цены теперь **цену устанавливает заведение**. Значит: цена подставляется динамически из сессии клуба (примеры в макете: «Order — 3,00 €»). Убрать все захардкоженные суммы.
2. **Обязательный экран условий перед оплатой** (сейчас его нет — по ТЗ он требуется):
   - «Вы платите {цена} за отправку запроса. Решение о воспроизведении остаётся за диджеем»
   - «Если несколько человек запрашивают одну песню, каждый запрос оплачивается отдельно»
   - «Песня может быть сыграна только один раз»
   - Кнопка подтверждения + ссылка на условия
3. **Канвас:** дубли экранов («My requests» встречается дважды), пустые зоны, разный масштаб фреймов — выровнять в сетку, пронумеровать флоу, удалить дубли.
4. Пустая папка-«легенда» в углу канваса — убрать или заполнить.

## 1. Приложение диджея (Flutter) — не начато

Экраны должны читаться **в темноте, одним взглядом, под музыку** — крупная типографика, минимум мелких элементов.

### 1.1. Логин
- Email/телефон + пароль, вход с 2FA (код из приложения-аутентификатора)
- «Забыли пароль?»

### 1.2. Выбор сессии
- Список активных сессий клуба на сегодня + «вступить в смену»
- Если клуб уже создал сессию — карточка: клуб, дата, стили

### 1.3. Настройка вечера
- Выбор принимаемых **музыкальных стилей** (чипы: Salsa, Bachata, Merengue, Rock, Jazz, …) — можно менять в течение ночи
- Цена запроса этой сессии (задаётся клубом — показать как read-only или настраиваемую, уточним)
- Тумблер **«Приём запросов: открыт / на пауза»** — крупный, доступный одной рукой

### 1.4. Очередь запросов (главный экран)
Список живых запросов, каждая карточка:
- Обложка трека, название, исполнитель
- **Количество запросов этой же песни** (×7) — выделить, это социальный сигнал
- Время поступления («2 мин назад»)
- Стиль
- Оплаченная сумма
Сортировка: новые сверху или по количеству запросов (переключатель). Обновление — в реальном времени, без перезагрузки.

### 1.5. Карточка/раскрытие запроса
- Крупное превью-действия: **Принять · Отклонить · Сыграна**
- Отклонение — с быстрым шаблоном причины (опционально: «не тот стиль», «уже играл», «не в настроении вечера») — отправляется гостю
- ISRC/идентификатор трека — для поиска в Rekordbox/Serato (мелко, для копирования)

### 1.6. «Сейчас играет»
- Текущий принятый трек + очередь следующих (принятые, отсортированные диджеем вручную — drag & drop)

### 1.7. Статистика вечера
- Запросов принято/отклонено/сыграно, заработано за вечер (сумма доли диджея), пик по времени

### 1.8. Состояния диджея
- Пауза приёма (баннер на главном экране)
- Пустая очередь («Запросов пока нет»)
- Офлайн/переподключение
- Завершение смены (сводка ночи)

## 2. Веб-панель ночного клуба — не начата

Desktop-first (но адаптив до планшета). Тот же стиль: чёрный/неон, но плотнее, чем мобайл.

1. **Логин клуба** (+2FA) + восстановление пароля
2. **Дашборд:** активная сессия сейчас, запросы за вечер, доход за сегодня/неделю/месяц, мини-графики
3. **Профиль клуба:** название, адрес, фото/логотип, контакт
4. **Онбординг в Stripe Connect** — шаги привязки банковского счёта (статусы: заполнено / на проверке / готово)
5. **Тарифы клуба (новое!):**
   - **Цена запроса** — задаёт заведение (мин/макс ограничены платформой)
   - Показ разреза: цена → комиссия DROP IT → доля клуба → доля диджея
   - История изменений цен (недавно введено в архитектуре)
6. **Сессии/вечеринки:** создание, привязка диджея, открытие/закрытие, история
7. **Генерация QR-кода:**
   - Превью QR + то, **что увидит гость после скана** (экран приветствия с этим диджеем и стилями)
   - Активировать/деактивировать, перегенерация на каждую сессию
   - Скачивание: PNG для печати (афиша/столики/стенд) + несколько размеров
8. **Доходы:** по вечерам, по диджеям, по трекам; вывод средств (кнопка + история выплат, статусы)
9. **Статистика:** топ запросов, пиковые часы, повторяемость треков
10. **Управление диджеями:** приглашение, привязка, статус выплат

## 3. Админ-панель DROP IT — не начато

Внутренний инструмент: те же цвета, но максимальная информационная плотность, таблицы.

1. **Дашборд:** активные сессии сейчас, запросы/мин в реальном времени, оборот за день/неделю, карта активности
2. **Клубы:** список, статус (активен/на паузе/заблокирован), тарифы, оборот, кнопка блокировки/приостановки
3. **Диджеи:** список, смены, выплаты
4. **Пользователи/гости:** устройства, антифрод-скоринг
5. **Платежи и комиссии:** каждый платёж, разрез сплита, статусы выплат, разбор инцидентов
6. **Инциденты и антифрод:** очередь тревог (подозрительные паттерны), разбор, действия
7. **Аудит-лог:** все действия админов (кто, что, когда) — append-only
8. **Тарифы платформы:** комиссия DROP IT (фикс/процент, per-club), мин/макс цена запроса

## 5. Сквозное для всех экранов

- **Дизайн-система как токены:** палитра (чёрный/белый/неон + серые уровни + красный для ошибок/отклонений), типографика (шкала, размеры «читаемо в темноте» для диджея), отступы, радиусы, состояния кнопок (default/pressed/disabled/loading), инпуты, тумблеры, чипы стилей
- **Состояния каждого экрана:** загрузка (скелетоны), пустое, ошибка, офлайн
- **Локализация:** сейчас всё на EN; закладываем RU/ES (тексты длиннее на ~30 % — не захардкодить размеры)
- **Push-уведомления гостя:** принят/отклонён/сыгран — нужны мини-макеты
- **Иконки:** минималистичные наушники (логотип) — проверить, есть ли финальная версия логотипа в векторе

## Порядок работ (предложение)

| Приоритет | Блок | Почему |
|---|---|---|
| 1 | Правки клиентских экранов (раздел 0) | Цена и обязательный экран условий — блокируют разработку оплаты |
| 2 | Приложение диджея | Ядро продукта: без него запросы обрабатывать некому |
| 3 | Панель клуба + QR-генератор | Без этого клуб не может запустить сессию |
| 4 | Админ-панель | Минимальный набор: клубы, платежи, блокировки |
| 5 | Состояния, дизайн-система, push | Параллельно с 2–4 |
| 6 | Лендинги | После утверждения продукта |

**Формат сдачи:** те же фреймы в pen.dev / экспорт в Figma, авто-лейауты, токены в переменных, тексты — editable (не растрировать), фреймы названы по схеме `[role]/[screen]/[state]`.
