# Product

## Register

product

## Users

DROP IT is used by platform operators, club staff, and DJs while a venue is preparing for or running a live session. Operators manage clubs, DJs, payments, payouts, incidents, and platform configuration. Club staff open a room, invite a DJ, monitor guest requests, and track session activity. DJs accept invitations and work through the live request queue.

These users work under time pressure and need to scan status, take the next action, and recover from errors without losing context.

## Product Purpose

DROP IT connects guests, clubs, DJs, and platform operations around live music requests and payments. The web surfaces should make the operational state of a room legible and make the next safe action obvious while preserving the existing API workflows.

Success means staff can operate a live room with low cognitive load, operators can resolve platform issues from a consistent control surface, and DJs can process requests quickly on desktop or mobile-sized screens.

## Brand Personality

Calm, precise, nocturnal. The interface should feel controlled and focused during a busy night: quiet surfaces, disciplined hierarchy, compact navigation, and restrained use of DROP IT green for important actions and states.

The interface may be quiet and dense, but it is not a copy of another product. Choose
layout and hierarchy from the task, the role, and the live state on screen.

## Anti-references

Do not turn the operational panels into a marketing landing page, neon club poster, or
decorative dashboard. Avoid oversized hero sections, gradients, glow, glass effects,
floating or nested card stacks, ornamental illustrations, random layout experiments,
unnecessary animation, unclear icon-only controls, and dense visual noise that hides live
status.

## Design Principles

1. Make the next operational action obvious.
2. Show live state before secondary detail.
3. Keep navigation compact and consistent across roles.
4. Use visual emphasis sparingly so urgent states retain meaning.
5. Preserve context and provide clear recovery when an API action fails.

## Accessibility & Inclusion

Target WCAG 2.2 AA practices for the web panels. Maintain readable contrast, visible keyboard focus, semantic controls, usable touch targets, clear status text beyond color alone, and reduced-motion behavior for non-essential transitions.
