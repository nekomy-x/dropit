# DROP IT — приложение диджея (Flutter)

Очередь запросов: карточки с ×N (социальный сигнал), крупные действия
Принять · Отклонить (шаблон причины) · Сыграна, тумблер приёма,
статистика вечера. Экраны читаются в темноте одним взглядом
(dizayn-zadanie §1).

## Статус

Каркас (см. `IMPLEMENTATION_STATUS.md`): все экраны §1, API-клиент по
контрактам `docs/openapi.yaml` (логин 2FA, очередь new|hot, действия
accept/reject/played с идемпотентностью, pause/resume, shift, stats).
Бэкенд-роуты DJ полностью реализованы (F4: queue, actions с no-op
семантикой, пауза).

## Запуск

```bash
cd apps/mobile-dj
flutter pub get
flutter test          # виджет-тесты (не требуют API)
flutter run           # API по умолчанию 127.0.0.1:8080
```

`test/responsive_test.dart` проверяет реальные экраны входа, очереди,
настройки вечера и статистики на 320/390/430 px, в горизонтальной ориентации
и с увеличением текста до 150%. Для очереди проверяется полезная ширина
текстового блока, а для раскрытого запроса — доступность нижнего действия
после прокрутки. Тесты используют локальный API-дублёр, без сетевых запросов.

## Структура

```
lib/

  api/api_client.dart   # логин 2FA (2 шага), очередь, действия, shift/stats
  screens/
    login_screen.dart   # §1.1: email+пароль → TOTP-код (крупное поле)
    queue_screen.dart   # §1.4/1.5: очередь + раскрытие (действия, ISRC)
    settings_screen.dart# §1.3: тумблер приёма (крупный), стили-чипы
    stats_screen.dart   # §1.7: заработок/принято/сыграно
```

## WS-live (gateway-ws 0.7.0)

`lib/api/ws_client.dart` — подписка на queue-канал смены:
`POST /v1/ws/ticket` → `GET /v1/ws?ticket=…` → первый кадр
`{"subscribe":"queue","id":"<session>"}`. События
(request.created с ×N, accepted/rejected, session.paused) применяются
редьюсером `lib/api/queue_state.dart` — очередь обновляется без
pull-to-refresh. Транспорт (web_socket_channel) подключается в
прод-сборке; в каркасе WS-клиент деградирует на ручной refresh
(connectQueueLive → false), контракт покрыт тестами через мок-стрим.

## Заглушки (правило 5 — помечены в коде)

- стили-чипы: персист не реализован на бэкенде (эндпоит не написан);
- «сейчас играет» (§1.6): принятые запросы видны в очереди со статусом
  OK; отдельный экран с ручной сортировкой (drag & drop) — кандидат
  след. итерации (WS-слой уже готов);
- обложки: иконка-заглушка до B5 (кэш каталога);
- пик по времени (§1.7): эндпоинт не реализован.

Прод: push-уведомления новых запросов, WS-обновление очереди
(gateway-ws, F9), secure storage токенов.
